# 提交时 PDF 转换进度条 — 设计

> 日期：2026-08-05
> 状态：已批准

## 背景

提交任务时，非 PDF 文件（Word/Excel/图片）由 ARQ Worker 后台异步转换为 PDF。当前等待期间前端只有提交按钮 loading + 文案「文件转换中，请稍候...」，用户无法感知转换进度，只能盲目等待。

LibreOffice 无头 CLI 转换单文件没有进度回调，无法获取文件内部百分比，因此采用「伪动画 + 真实状态校正」的混合方案，避免纯假数字误导。

## 方案

当前节点文件列表**每个文件行**显示一条迷你进度条，仅在转换进行中（`waitingConversion`）显示，转换完成后消失。

### 状态机

| 文件状态（轮询真实值） | 进度条表现 |
|------------------------|------------|
| pending（等待转换） | 迷你条停在 0%，文案「等待中」 |
| converting（正在转换） | 动画 0→95% 封顶，文案「转换中」 |
| ready（转换完成） | 进度条消失（无徽标，可预览） |
| failed（转换失败） | 红色进度条 + 「转换失败」，保留现有弹错 |

### 数据流

- 状态来源：现有 `getFilesStatus` 轮询（每 2s），返回每个文件的 `conversion_status`
- 动画驱动：前端定时器（约 200ms/帧）推进所有 `converting` 文件的进度，上限 95%
- 校正：轮询发现某文件 `ready` → 进度补到 100% 后消失；`failed` → 置红
- 说明：Worker 顺序排队转换，实际同时仅一个文件在转；其余文件停在「等待中」，各自到 0% 等待

### UI 位置

- 文件夹模式与简单模式的文件行均显示，位于文件行右侧（原徽标位附近）
- 迷你条宽度约 72px，el-progress 或纯 CSS 实现，贴合现有行高
- 转换开始前/结束后不显示进度条，仅 `waitingConversion` 期间可见

## 涉及文件

仅 `frontend/src/views/profile/TaskDetail.vue`（进度状态 ref、动画定时器、轮询校正、迷你条模板与样式）。后端零改动。

## 边界与失败处理

- 动画永不虚报 100%：封顶 95%，真实完成才补 100%
- 某文件转换失败：该行红色提示，整体保留现有 `ElMessage.error` 弹错逻辑
- 页面离开（组件卸载）时清理动画定时器（沿用现有轮询清理模式）
- 转换完成后文件列表徽标随详情刷新消失（沿用 2026-08-05 已修逻辑）

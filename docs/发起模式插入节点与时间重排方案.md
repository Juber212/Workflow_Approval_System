# 发起模式插入节点与时间重排 — 需求与实施方案（计划文档）

> 状态：**计划阶段**（代码未落地，评审通过后再实施）
> 日期：2026-08-11
> 用途：沉淀「发起模式插入节点 + 时间自动重排」需求与设计，供评审后开发

---

## 一、需求背景

发起项目进入流程设计器（发起模式）后，各节点截止日期已按模板顺序 + 节点时限自动排列好。业务上有时需要在发起时**临时插入一个节点**（调整本次流程的工序结构），插入后：
- 新节点需要有截止日期（时限）
- **插入位置之后的节点时间自动顺延**（为新节点腾出时间）

当前 M17 拦截「发起模式新增工作节点」（避免污染共享模板），插入节点无法生效，且画布时间不重排。

---

## 二、现状分析

| 项 | 现状 |
|----|------|
| 发起时间预填 | 加载模板时按 `today + time_limit_days` 顺排每节点 `plan_begin/deadline`（`FlowDesigner.vue` 调用 `calculateDeadlines`） |
| M17 拦截 | `FlowDesigner.vue` 检测到新增工作节点（`hasNewWorkNode`）→ 提示「不会进入实例」并阻止发起 |
| deadline 级联 | `PropertyPanel.vue` 修改节点 deadline 时，调 `calculateDeadlines` 级联顺延下游（**可复用**） |
| 实例创建 | `create_instance` 从模板复制节点 + `node_overrides` 覆盖，**不支持动态新增节点** |

---

## 三、实施方案

### 3.1 时间重排（前端，阶段1）

**插入节点后的重排逻辑**（复用 `calculateDeadlines`）：
```
画布插入新节点:
  1. 给新节点默认时限（取前一个节点的 time_limit_days，缺省 1 天）
  2. 定位插入位置 → 以前一节点 deadline 次日为 begin 锚点
  3. 调 calculateDeadlines 从插入位置顺排：新节点 + 后续所有节点
  4. 写回各节点属性 plan_begin / deadline（后续节点自动顺延为新节点腾时间）
```
- 触发：监听画布「新增节点」事件（LogicFlow node:add / 预设拖入）
- 复用 `PropertyPanel.vue` 已有的级联写回逻辑（抽成公共函数）

### 3.2 放开 M17 + 后端动态节点（阶段2）

**前端**：
- 移除发起模式新增工作节点拦截（`hasNewWorkNode` 提示）
- 发起时提交新增节点定义（名称/负责人/校验人/审批人/批准人/时限/文件夹/签名配置等，含 sort_order 位置）

**后端 `create_instance`**：
- 支持「模板节点 + 发起新增节点」合并创建实例节点：
  - 按 sort_order 合并模板节点与新增节点，重排全部节点顺序
  - 动态创建新增节点的 InstanceNode（含人员/时限/文件夹/签批配置）
  - 连线处理：插入点前后节点与新节点建立 InstanceEdge
  - 难度4 校验：新增工作节点也需配置批准人
  - 节点人员校验：新增节点人员复用 `validate_user_ids_exist`
- 新增节点数据经 `node_overrides` 扩展（或新增字段）传递

**不改共享模板**：新增节点只进实例快照（与模板解耦，沿用发起模式现有约定，不写回模板）。

### 3.3 触发与展示
- 发起时：新增节点纳入实例 → 正常执行（负责人收 Task 等）
- 实例详情/进度：按合并后的节点顺序展示

## 四、待定项（需业务确认）

| # | 待定项 | 说明 |
|---|--------|------|
| 1 | 新增节点配置范围 | 是否允许配置完整节点（签批/文件文件夹/批准人），还是仅基础（名称/人员/时限） |
| 2 | 插入位置规则 | 新增节点默认插到哪个位置（当前选中节点后？还是末尾），后续能否拖动调整顺序 |
| 3 | 连线语义 | 插入节点后，上游到新节点、新节点到下游的连线是否需手工调整，还是自动直连 |
| 4 | 并发/快照 | 发起时结构调整是否记录快照（不影响模板），重发/换人等场景的处理 |

---

## 五、分阶段实施建议

| 阶段 | 内容 | 说明 |
|------|------|------|
| **阶段1 前端时间重排** | 画布插入节点后级联重排时间（`calculateDeadlines`），M17 暂不放开 | 画布预览时间正确，发起仍拦截 |
| **阶段2 放开 M17 + 后端动态节点** | 移除拦截，`create_instance` 支持新增节点合并 | 发起时插入节点真正生效 |
| **阶段3 完整配置** | 新增节点完整配置（签批/文件夹/批准人/连线调整） | 功能完善 |

---

## 六、风险与影响

- **M17 放开风险**：发起时可改节点结构——须确保**只影响实例快照、不写回共享模板**（沿用发起模式 node_overrides 解耦约定，避免并发发起互相覆盖）
- **后端动态节点复杂度**：create_instance 从「纯复制模板」变为「模板+新增合并」，涉及节点复制/排序/连线/校验，改动较大
- **时间一致性**：重排逻辑须与现有 deadline 计算（`calculate_deadlines`）口径一致，避免计划与实际脱节
- **难度4**：新增工作节点也须满足难度4 的批准人配置约束

---

## 七、验收要点

1. 发起模式画布插入节点 → 新节点有 deadline，后续节点时间自动顺延（前端重排）
2. 发起时新增节点进入实例（M17 放开后），负责人收到任务，流程正常流转
3. 共享模板不受发起时插入影响（不写回模板）
4. 难度4 新增节点校验批准人
5. 前端 vue-tsc 0 错 + build 过；后端 329 测试全绿

# 自动排产 — 需求与实施方案（计划文档）

> 状态：**计划阶段**（代码未落地，评审通过后再实施）
> 日期：2026-08-11
> 用途：沉淀自动排产需求与实施设计，供业务评审、规则确认后开发

---

## 一、需求背景

系统是「以流程驱动项目的业务管理平台」。当前项目/方案发起后，各流程节点（工序）的负责人、时间由人工安排，缺乏**全局生产排产**视角——谁在什么时间做什么、资源是否冲突，无法直观掌握。

**自动排产**目标：项目/方案发起时，自动按流程节点生成排产计划（每道工序的时间线 + 分配的负责人），以甘特图直观展示。

---

## 二、已确认需求口径

| # | 口径 | 说明 |
|---|------|------|
| 1 | 触发时机 | **发起时自动排产**（生成整个排产计划） |
| 2 | 工序来源 | **流程模板的工作节点**（排除开始/结束节点，按 sort_order 顺序） |
| 3 | 时间计算 | **自然日顺排**（老板确认不用工作日概念），从发起日按节点时限 time_limit_days 逐节点衔接 |
| 4 | 资源 | **现有用户**当资源 |
| 5 | 产能约束 | 每人**同时只能做一个**任务（时间窗口不重叠，排他） |
| 6 | 展示 | **实例详情页甘特图**（每工序计划开始-结束 + 负责人） |

## 四、实施方案

### 4.1 后端

**新表 `schedule_items`（排产计划项）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | |
| instance_id | int | 所属实例 |
| node_id | int | 对应实例节点 |
| assignee_id | int | 排产分配的负责人 |
| plan_start_date | Date | 计划开始（自然日） |
| plan_end_date | Date | 计划结束 |
| duration_days | int | 工期 = time_limit_days |
| sort_order | int | 工序顺序 |

> 排产独立于流程执行（排产是「计划」，流程是「执行」），存新表不污染流程节点；全新库 `deploy_db` 自动建，已有库补建一次。

**排产算法（`schedule_service`）**
```
对每个工作节点（按 sort_order 顺排）:
  plan_start = 上一节点 plan_end + 1 天（首节点 = 发起日）
  plan_end = plan_start + time_limit_days - 1
  候选 = 节点人员（负责人 > 校验人 > 审批人 > 批准人，去重）
  若 [plan_start, plan_end] 有空闲候选 → 分配
  若全忙 → 选最早空闲者（其已有排产最晚结束 + 1 天），节点顺延到该窗口
```
- 资源冲突检查：同一用户时间窗口不重叠（跨实例也检查）
- 幂等：重排前清旧排产

**触发 + API**
- `create_instance` 节点复制后调用排产（同事务）
- `GET /instances/{id}/schedule` → 排产列表（含节点名/负责人名）

### 4.2 前端

- **`GanttChart.vue`**（手绘 SVG）：X 轴日期刻度，Y 轴工序泳道，条 = 计划区间；复用 `TrendChart.vue` 模式，无第三方库
- **`InstanceDetail.vue`**：粘性头部后加可折叠「排产计划」卡片，内嵌甘特图
- `api/instance.ts`：`getInstanceSchedule` + `ScheduleItem` 类型

## 七、风险与影响

- **排产与实际执行脱节**：排产是计划，实际执行可能提前/延后（负责人请假、驳回重做），甘特展示的是「计划」而非「实际」——需在甘特上区分计划/实际，或后续加实际进度对照
- **资源规则未定**影响分配合理性：阶段1 用节点配置人员，若业务要求跨所/难度规则，阶段2 前需明确
- **权限**：排产全员可见（与实例详情一致）；排产 API 需与详情同权限
- **性能**：排产算法 O(节点数)，发起时执行开销可忽略
